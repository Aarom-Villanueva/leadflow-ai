## Riesgos y siguiente acción

Esta propuesta documenta primitivos observados en **una** sesión de Claude Code Cloud (este entorno en la nube), nunca en el equipo del propietario ni en cualquier otro entorno de producción candidato (runner de GitHub Actions, otra infraestructura). Que un binario exista en `PATH` no demuestra que el mecanismo que ofrece funcione como aislamiento real: esta entrega distingue explícitamente presencia de eficacia verificada, y no construye ni prueba ningún namespace/cgroup/contenedor real. Se publica como PR en borrador, solo documentación, sin fusionar. El siguiente paso, solo si el propietario autoriza tras la revisión, es: (a) decidir el entorno de producción real para el Executor sandbox, (b) autorizar la construcción y verificación real (no solo la presencia) de los mecanismos propuestos en ese entorno concreto, y (c) una propuesta de implementación separada, con su propia reserva, archivos exactos y pruebas — nunca una activación automática.

## Limitaciones explícitas

Esta propuesta es, por diseño, una inspección de solo lectura de un único entorno (esta sesión de Claude Code Cloud) y una documentación de intención — no una implementación, no una prueba de que algo funciona, y no evidencia aplicable a ningún otro entorno sin su propia inspección separada. En particular:

- **No se construyó ni se probó ningún namespace, cgroup, chroot ni contenedor real**: la presencia de binarios (`unshare`, `runc`, `chroot`, una jerarquía `cgroup` escribible) es evidencia de que un sandbox local no es obviamente imposible aquí, nunca de que ya exista uno funcional.
- **Nada aquí se aplica al equipo del propietario (Windows) sin verificación propia**: su sistema operativo, nivel de privilegio, herramientas instaladas y módulos de seguridad del kernel son desconocidos desde esta sesión y pueden ser completamente distintos (empezando por no ser Linux).
- **Ninguna comprobación bloqueada por host de red denegado, secreto ausente o recurso agotado se presenta como superada**: cada bloqueo real encontrado durante la inspección se documenta explícitamente en la propuesta (operación intentada, host si es identificable, y la limitación concreta que impone), nunca se omite ni se sustituye por una suposición.
- **No se solicita ninguna credencial nueva**: un aviso de secreto ausente durante esta inspección de solo lectura no se interpreta como una necesidad de aprovisionar una clave de API real para el ejecutor — el diseño de LF-001d exige exactamente lo contrario (el ejecutor nunca recibe credenciales).
- **La sección 14 de `docs/autopilot/LF-001d-IMPLEMENTATION-DESIGN.md` sigue vigente sin reducirse**: esta propuesta informa la decisión pendiente de la sección 11 de ese documento, no la resuelve ni demuestra ninguno de los controles que esa sección 14 ya señala como no demostrables sin un entorno y una tecnología de aislamiento real elegidos y construidos.

Nada de lo anterior se presenta como evidencia operativa.
