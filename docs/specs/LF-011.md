# LF-011 — Endurecimiento de pruebas AUTOPILOT previo a LF-001d

**Estado:** propuesta pendiente de revisión. Responsable: ChatGPT (implementación de pruebas); revisor propuesto: Claude Code. Base: PR #6 integrado en main, commit `3c88393995e4a62700fba0eefe24d6b059a104c6`.

## Objetivo y restricciones

Completar la cobertura individual de las 7 condiciones de denegación M1 identificadas por la auditoría independiente de LF-001c y eliminar código inalcanzable/manejadores frágiles de entradas malformadas, sin introducir conectores ni permisos. LF-011 es una tarea de endurecimiento, no la integración real LF-001d.

## Alcance

- Añadir `tests/coordination/simulator-hardening.test.mjs` con pruebas independientes de: `invalid_task_id`, `invalid_spec_path`, `invalid_backlog`, `invalid_other_reservations`, `invalid_lease_state`, `invalid_parallel_limit`, `invalid_reservation`.
- Casos adicionales: glob reservado por otro agente, valores `null`, tarea duplicada, intento 1 rechazado, aprobación `SIM-` obligatoria aunque el costo simulado sea cero.
- Hacer que `simulateAdmission` responda con `denied` frente a entradas de arrays/registros malformados en vez de estrellarse con `TypeError`; simplificar la comprobación de solapamiento inalcanzable, sin cambiar permisos ni semántica del simulador.
- Mantener `simulateTransition` solo como simulación; los indicadores de Git y aprobación siguen siendo declaraciones del fixture, **no evidencia real**. No habilitar reintentos efectivos ni conectar APIs de IA.
- Cerrar LF-001c en `docs/HANDOFF.md` solo mediante evidencia del merge PR #6; registrar LF-011 como reserva activa para el nuevo PR.

## Exclusiones

Sin SDK, API keys, pago, secretos, despliegue, agentes, permisos de escritura adicionales, auto-merge ni cambios a `docs/autopilot/BACKLOG.json`. El backlog conserva `execution_enabled=false`.

## Aceptación

1. Pruebas antiguas y nuevas en Node 24, ejecutadas por CI, sin regresiones.
2. Al menos una prueba individual para cada una de las siete razones M1.
3. Entradas de reserva o backlog malformadas no pueden generar un `would_admit`.
4. `Coordination gate` y `Foundation verification` satisfechos para el SHA de revisión.
5. Un segundo agente revisa independientemente los cambios, con énfasis en rutas de error y reglas de fail-closed.
6. Propietario autoriza por separado el merge. **No autoriza LF-001d ni operaciones reales.**

## Riesgos residuales

Este es un simulador de escenarios, no un motor de autorización desplegable. No demuestra autenticación real del propietario, control de gasto en proveedor ni verificación del historial Git para transiciones `done`. Para LF-001d hará falta un adaptador de confianza con controles y permisos específicos y aprobación explícita.
