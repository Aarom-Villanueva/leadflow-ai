# LF-026 — Prospectos y pipeline persistentes

Responsable ChatGPT; revisión independiente de Claude pendiente. Base `676946c93c2582dd6a033debf253bf1eb576c6e4`. El propietario autorizó este incremento tras integrar LF-025. No autoriza merge ni despliegue.

## Contrato de producto

Conectar el diseño aprobado con CRUD sin borrado definitivo: crear, listar, buscar/filtrar, consultar ficha, editar, asignar y archivar prospectos. Pipeline por organización con etapas open/won/lost; mover una tarjeta persiste y registra un evento. Owner/admin configuran etapas; sales gestiona prospectos pero no etapas. No hay ACL privada por vendedor: visibilidad compartida dentro de la organización, como DATA_MODEL/SECURITY.

Nombre obligatorio; contacto/origen opcionales. Email normalizado sin unicidad ni fusión automática; teléfono solo en E.164 explícito, sin adivinar país. Lead pertenece a organization y stage del mismo tenant; responsable opcional referencia membresía del mismo tenant y debe estar vigente al asignarlo. Revocar membresía no elimina historia. Fechas UTC, vistas con zona de la organización.

## HTTP y concurrencia

Rutas explícitas bajo `/api/organizations/:org`: leads GET/POST; leads/:id GET/PATCH; leads/:id/archive POST; leads/:id/history GET; pipeline GET; stages POST; stages/:id PATCH. No DELETE. Sesión real, origen para mutaciones, validación estricta y cuerpo acotado. No aceptar role/actor/organization_id del cuerpo. IDs ajenos o inexistentes 404, falta de capacidad 403, versión antigua o etapa usada 409, entrada inválida 422. Sin datos sensibles en errores o auditoría.

Listados con límite máximo 50, cursor estable por fecha/id o nombre/id y filtros acotados. Fechas de orden timestamptz(3) para conservar precisión del cursor en JavaScript. El cursor no es autoridad ni permite saltar RLS. Pipeline carga páginas acotadas, no promete contar filas no cargadas.

Edición/movimiento/archivo exigen version positiva actual. Bloqueo de fila + versión; el servidor incrementa version. Un cambio concurrente no se sobrescribe. Archivo conserva fila, eventos y auditoría y bloquea nuevas ediciones. Crear/mover prospecto y su evento/auditoría se confirman o revierten juntos mediante triggers.

## PostgreSQL y compatibilidad

Migración 0002 aditiva sobre LF-025, sin modificar 0001. Runner local explícito con provisionador separado: verifica objetos/propietario de identidad y rol runtime, rechaza instalaciones ambiguas y lleva checksum de la migración. Reaplicación con checksum idéntico no modifica datos; cambio de checksum se rechaza. Backfill de pipelines/etapas de organizaciones existentes y bootstrap atómico para organizaciones nuevas.

FKs compuestas por tenant para etapa, responsable y eventos. RLS en las cuatro tablas comerciales; FORCE en leads/eventos, owner exento en pipelines/stages para las funciones mínimas de bootstrap/bloqueo. Runtime no propietario ni miembro de roles propietarios, sin BYPASSRLS. Grants mínimos: sin DELETE de leads y sin mutación directa de eventos/auditoría. Contexto user/organization/request transaction-local desde sesión y membresía; bloqueo compartido de membresía vigente durante la operación. Helpers security definer con search_path fijo y EXECUTE restringido. Etapas configuradas bajo bloqueo del pipeline: orden serializado, nombre único, desactivación/tipo incompatible de etapa usada rechazados; conservar al menos una etapa activa de cada kind.

## Contrato compartido v1 y compatibilidad

Esquema aditivo 0002 y contratos estrictos en `src/modules/leads/contracts.ts`; solo se propone integrarlos mediante este PR revisable. LF-025 y 0001 no cambian de comportamiento de acceso. `pipeline` devuelve pipeline, timezone, stages, members y role reales; list devuelve leads/nextCursor, detalle y mutaciones lead, history events, configuración stage. Las claves de contacto son email/phoneE164/source/assignedUserId (nullable); stageId obligatorio al crear. PATCH parcial exige version y al menos un campo editable. Configuración de etapa admite name/kind/position/active/version. No se aceptan campos desconocidos ni parámetros de listado duplicados. Cuerpo máximo 4096 bytes, límite persistido 120 mutaciones/minuto por identidad y organización; mismo límite con UUID en mayúsculas. Los códigos 401/403/404/409/422/429/503 no incluyen SQL ni valores del usuario.

Contexto transaccional con `lf_lock_membership` y funciones mínimas SECURITY DEFINER con search_path fijo. FORCE RLS comercial en leads/eventos; pipelines/stages permiten bootstrap del propietario. Contexto y servidor runtime confiables, no autorización para exponer acceso SQL. La migración se serializa y su ledger debe pertenecer al provisionador original. Grants no conceden DELETE ni escritura de eventos/auditoría al runtime. Historial vinculado a IDs, no copia de nombres antiguos.
