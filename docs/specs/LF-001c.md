# LF-001c — Simulador estricto de admisión (sin IA, sin red)

**Estado:** propuesta para revisión técnica independiente. Responsable ChatGPT (preparación), revisor propuesto Claude Code. Base: merge LF-001b en `main` `3d8a4bf0931aca31fffc8105bd753a8bd78783d1`.

## Propósito
Convertir el diseño de `docs/autopilot/PHASE-2-DESIGN.md` en verificaciones deterministas puramente **simuladas**, sin ejecutar tareas reales.

## Alcance
1. `scripts/autopilot/simulate.mjs`: admisión por escenario local con rechazo cerrado ante estados o identidades inválidas, spec vacía/hash cambiado, base SHA inconsistente, dependencias sin resolver, decisiones sin fuente independiente, conflicto de reserva o lease, falta de permiso simulado, presupuesto simulado no autorizado, exceso de concurrencia o intentos inválidos.
2. Un resultado `would_admit` **NO autoriza ni ejecuta** agente alguno. Es solo el resultado del fixture para una futura revisión. La salida indica explícitamente `simulation-only`.
3. Transiciones simuladas sin saltos: `admitted→running→review→ready_for_owner→done`; revisión por agente distinto, `done` solo si la evidencia de entrada declara aprobación del propietario y merge verificable. El motor no consulta Git para verificarlo todavía.
4. Pruebas positivas/negativas sin red, incluyendo replay (clave idempotente), falsificación, límites, suspensión, contexto desactualizado y bloqueos.
5. Ejemplo de escenario denegado `docs/autopilot/fixtures/denied.json`; workflow `workflow_dispatch` manual, solo lectura, Node fijado por `.nvmrc`.
6. Registro del merge previo de LF-001b con prueba real contra historial Git, y reserva propia LF-001c en ROADMAP/HANDOFF.

## Límites deliberados y riesgos

- **No hay despachador, agentes, invocación a SDKs, GitHub API, secretos, persistencia de leases, compras, migraciones ni despliegues.**
- El `specText` y las `policy` de los fixtures son escenarios sintéticos de prueba: el simulador no puede demostrar autenticidad ni permisos reales. **No usar su `would_admit` como autorización ejecutable.**
- `approval_id` en fixtures tiene prefijo `SIM-`, no es una aprobación real del propietario; no se infieren decisiones de `BACKLOG.json`.
- Límites expresados en centavos son valores de prueba, no capacidad de controlar facturación real. Cualquier ejecución futura requiere presupuesto externo aprobado y una identidad autorizada.
- La evidencia de un `done` simulado es solo input de prueba. Un sistema operativo deberá verificar el merge real contra Git protegido, como `check-coordination.mjs`.
- La detección de conflictos del fixture es una condición necesaria pero no sustituye el check de coordinación en CI ni la revisión humana.
- La ruta de spec, base SHA y reservas son inputs sintéticos; LF-001d necesitará adaptadores que lean fuentes inmutables y resistan alteraciones de usuario.
- No alterar `execution_enabled=false` de `docs/autopilot/BACKLOG.json`.
