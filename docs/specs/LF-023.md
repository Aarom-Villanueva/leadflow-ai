## 3. Evidencia del esquema de Better Auth (investigación, no instalación)

Para no adivinar los nombres/tipos de columna del adaptador, se descargó (vía `npm pack`, a un directorio de scratch fuera del repositorio, inspeccionado y borrado — nunca instalado en `node_modules` ni añadido a `package.json`) el paquete publicado `@better-auth/core@1.7.18` y se leyó directamente `src/db/get-tables.ts`, la función `getAuthTables` que el propio paquete `better-auth@1.7.18` importa para construir su esquema. Confirmado por lectura directa del código fuente de esa versión exacta, no por documentación ni por memoria:

| Tabla | Columnas (tipo; requerido; notas) |
|---|---|
| `user` | `id` (string, PK implícita); `name` (string, requerido); `email` (string, requerido, único); `emailVerified` (boolean, requerido, por defecto `false`); `image` (string, opcional); `createdAt`/`updatedAt` (date, requeridos) |
| `session` | `id` (string, PK); `expiresAt` (date, requerido); `token` (string, requerido, único); `createdAt`/`updatedAt` (date, requeridos); `ipAddress`/`userAgent` (string, opcionales); `userId` (string, requerido, FK → `user.id`, `onDelete: cascade`, indexado) |
| `account` | `id` (string, PK); `accountId`/`providerId` (string, requeridos); `userId` (string, requerido, FK → `user.id`, `onDelete: cascade`, indexado); `accessToken`/`refreshToken`/`idToken`/`scope`/`password` (string, opcionales, los primeros tres y la contraseña nunca devueltos al cliente); `accessTokenExpiresAt`/`refreshTokenExpiresAt` (date, opcionales); `createdAt`/`updatedAt` (date, requeridos) |
| `verification` | `id` (string, PK); `identifier` (string, requerido, indexado); `value` (string, requerido); `expiresAt` (date, requerido); `createdAt`/`updatedAt` (date, requeridos) |

Ninguna tabla tiene `organization_id`: esto confirma, por evidencia directa del código (no por suposición), que las cuatro tablas de identidad son globales, nunca sujetas a RLS por tenant — exactamente la pregunta que `docs/specs/LF-002a.md` plantea y que el spike debe demostrar en tiempo de ejecución, no solo en el esquema declarado.
